深色模式最省事的实现是 `filter: invert(1)`，或者把写死的颜色挨个换成反色。这两种出来的东西都很难看。

难看的原因不是「审美」，是**明度关系变了**。浅色底上，正文墨色和背景的明度差大概 10:1；直接反相之后，这个比值还在，但眼睛对「亮底暗字」和「暗底亮字」的对比感知并不对称 —— 同一组灰色放到深底上，看着会明显更暗、更脏。

所以这个站的深色不是反色，是另一套取值。

## 只保证关系，不保证数值

浅色是一张纸：暖纸白 `#f3f2ee` 打底，暖墨色 `#1f0909` 写字。

深色没去反相它，而是挑了深灰蓝 `#16181c` 打底、米白 `#e8e6e1` 写字。选深灰蓝而不是纯黑，是因为纯黑底上的纯白字在小字号时会明显发光（halation），看十分钟就累。

真正要保持一致的不是色值，是这几条关系：

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 背景 | `#f3f2ee` | `#16181c` |
| 正文 | `#1f0909` | `#e8e6e1` |
| 分隔线 | `#d6d2c9` | `#2e323a` |
| 链接 | `#065588` | `#7fb4dd` |
| 数据/强调（唯一的彩色） | `#0d9488` | `#2dd4bf` |

注意链接在深色里变亮了（`#065588` → `#7fb4dd`），不是变暗。因为深底上深蓝色直接看不见 —— 「同一个色号」在两种底色上根本不是一个东西。

## 落地：组件里不写判断

所有颜色都是 CSS 变量，深色只覆盖同名变量的值：

```css
:root {
  --bg: #f3f2ee;
  --ink: #1f0909;
  --link: #065588;
}

[data-theme='dark'] {
  --bg: #16181c;
  --ink: #e8e6e1;
  --link: #7fb4dd;
}
```

组件里永远只写 `var(--bg)`。加主题不需要动任何组件，改的只是取值。这条看起来是常识，但它决定了一件事：**以后改配色不用全局搜索颜色值**。

## 坑一：白闪

主题存在 `localStorage` 里，而 `localStorage` 只有在 JS 执行之后才读得到。

如果等 Vue 启动再设 `data-theme`，深色模式的用户每次刷新都会先看到一帧白底，然后猛地切成深色。这一帧就是 FOUC，比加载慢还刺眼。

正确做法是在 `<head>` 里放一段**同步执行**的内联脚本，在样式表生效之前就把 `data-theme` 写到 `<html>` 上：

```html
<script>
  try {
    var t = localStorage.getItem('p2026:theme')
    if (t === 'dark' || t === 'light') document.documentElement.setAttribute('data-theme', t)
  } catch (e) {}
</script>
```

三个要点：

1. **必须内联**，不能是外部脚本 —— 外部脚本要等一次网络往返，那一帧已经闪完了。
2. **必须同步**，不能加 `defer` 或 `async`。
3. **必须放在样式表之前**，否则浏览器已经按浅色算了一遍样式。

这个站一开始没有这段脚本（`<html data-theme="light">` 是写死的），深色用户每次刷新都会闪一下。是写完这篇文章回头看代码才发现的。

## 坑二：图表是白底的

站内所有图表都是构建时生成的图片，底子是浅色的纸白。

结果就是：深色模式下，正文是深底，图表是一块亮白的长方形。它不「错」，但很突兀 —— 像贴了一张打印稿在深色纸上。

三个处理方式：

1. **给图片加边框**，让它看起来像「贴在页面上的一张图」，而不是漏了一张底。这是现在的做法，成本最低。
2. **生成两套图**（浅底/深底），按主题切换 `src`。问题是主题是运行时状态，`<picture>` 的媒体查询只能跟系统偏好，跟不了手动切换。
3. **不生成图片，用 CSS 画**。适合简单的数字块，不适合带坐标轴的图表。

我选了第 1 种。第 2 种不是做不到（把 `src` 换成一个随主题变化的绑定就行），但它会让每张图多一份产物，而且换主题时会有一瞬间的空白 —— 用一个更差的体验去修一个观感问题，不划算。

## 一条原则

**深色模式不是在浅色上做减法，是另做一套。** 任何「自动转换」的方案（反相、滤镜、调亮度）都会在某一张截图上露馅 —— 通常是图片、代码高亮、或者是那个被改成灰紫的暖色。
