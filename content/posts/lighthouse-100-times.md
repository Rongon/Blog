第一次跑 Lighthouse 拿到 62 分，改了两行代码再跑，74 分。又改回去，81 分。那时候我以为是工具坏了。

后来才知道：**Lighthouse 的分数本身有方差**。同一份代码连跑十次，性能分可以差出 20 分。

![从高处看的海岸线](/images/photos/coast-02.jpg)

*第一次意识到「数据不可复现」的时候，正好在海边。*

## 方差从哪来

三个来源，按影响从大到小：

1. **网络节流是模拟的**。Lighthouse 用一组合成的延迟和带宽参数去"假装"慢网络，但和你真实的网络抖动不是一回事。
2. **机器负载**。你后台开着 Docker、VS Code、几个浏览器标签，CPU 抢占会让主线程时间成倍波动。
3. **第三方脚本**。任何一个异步加载的东西都可能落在关键路径上，也可能不落。

## 我最后用的测法

- **固定条件**：同一台机器、同一个 Chrome 版本、关掉所有无关窗口、每次都清缓存
- **跑五次取中位数**，不看最好那次也不看最差那次
- **把 JSON 原文存档**，而不是只记那个分数——出问题的时候要回去看具体是哪一项变了

```bash
for i in 1 2 3 4 5; do
  npx lighthouse http://localhost:4173 \
    --preset=desktop \
    --output=json \
    --output-path=./perf/home-run-$i.json \
    --quiet
done
```

## 最重要的一条

**分数是给别人看的，原始数据是给自己用的。**

我最后留在仓库里的是五个 JSON 文件，不是一句「优化了 40%」。因为面试的时候，对方真正会问的不是分数，是「你怎么知道它变快了」。
