第一次跑 Lighthouse，62 分。改了两行代码再跑，74 分。把这两行改回去，81 分。

那时候我以为是工具坏了。后来才明白：**它每一次给你的都是一个估计值，不是一个测量值。**

同一份代码，同一台机器，连跑五次，性能分能在 38 到 52 之间跳（优化前那一批），也能在 94 到 97 之间跳（优化后那一批）。差的不是代码，是每次跑的时候机器和网络的状态。

所以这个仓库的 `perf/` 目录里现在躺着 50 份 JSON，一共 44.6 MB。这篇文章说的是为什么需要这么多。

## 方差有多大

我把同一批构建的三次、五次实测摊开：

| 批次 | 单次分数 | 极差 |
| --- | --- | --- |
| 代码分割那一版（3 次） | 95 / 93 / 91 | 4 |
| 按需引入那一版（3 次） | 90 / 98 / 97 | 8 |
| 图片质量那一版（3 次） | 95 / 89 / 94 | 6 |
| 冷缓存优化后 | 95 / 94 / 94 / 97 / 95 | 3 |
| 冷缓存优化前 | 38 / 46 / 46 / 52 / 43 | 14 |

「按需引入」那一批最能说明问题：90 和 98 是同一天、同一个构建、同一台机器跑出来的，中间只隔了几分钟。如果我只跑一次，我会得出「这一项让分数从 93 掉到 90」或者「涨到 98」这两种完全相反的结论 —— 而它们都不是真的。

FCP 也一样。同一份构建，我见过 630 ms，也见过 1,314 ms，差一倍。

![同一份代码连跑 5 次，优化后与优化前的分数分布](/images/tech/perf-score-runs.webp)

## 方差从哪来

按影响从大到小：

1. **节流是模拟的**。Lighthouse 不是真的把网络限速到 4G，而是按公式算「如果在这种网络下，这些资源需要多久」。模型的输入是你的机器此刻跑出来的时间，机器一抖，结果就跟着抖。
2. **机器负载**。后台开着 Docker、编辑器、十几个浏览器标签，CPU 抢占会让主线程时间成倍波动。我后来会把本地 dev server 和之前的 Lighthouse 进程全部关掉再跑。
3. **缓存**。第二次跑比第一次快，经常只是因为字体和图片已经在磁盘缓存里了。

## 我的测法

五条，都是踩出来的：

1. **只测构建产物**，不测 `pnpm dev`。dev 服务器不做拆分、不做压缩，那里测出来的数字没有参考意义。
2. **每次都清缓存**。用一个全新的 Chrome 用户目录（`--user-data-dir`），跑完删掉。
3. **跑三到五次，取中位数**。不报最好那次，也不报最差那次。
4. **关掉其他服务器**。本地 preview、之前挂着的仿真服务，全部先停。
5. **把 JSON 原文存进仓库**，不只记分数。

```bash
# 每次都用一个全新的用户目录，跑完删掉
for i in 1 2 3 4 5; do
  npx lighthouse https://rongon.github.io/Program2026/ \
    --preset=desktop \
    --output=json \
    --output-path=./perf/cold-fast-run$i.json \
    --chrome-flags="--user-data-dir=$(mktemp -d)" \
    --quiet
done
```

第 2 条是后来加的。之前我都是直接跑，跑出来的数字一次比一次好，我以为是优化的功劳 —— 其实是缓存。

## 什么才是确定信号

Lighthouse 的分数会跳，但有一个东西不跳：**字节数**。

首屏请求了多少 KB、脚本多少 KB、图片多少 KB，这些是同一份产物、同一批请求下的固定值，跟机器负载没关系。我在优化过程中做的判断，基本都是看字节数做的：

- 图片从 30.6 MB 降到 901 KB，这个幅度不需要 Lighthouse 来确认。
- 反过来，懒加载那一项我测出「桌面省 0 字节」—— 如果只看分数，它在 77 和 93 之间动，我会以为它有用。

分数是给别人的一个汇总信号，字节数才是自己能拿来做决定的东西。

## 为什么要存 50 份 JSON

不是为了存档好看，是因为**出问题的时候要能回去看是哪一项变了**。

有一次 FCP 从 430 ms 变成 470 ms，分数从 97 掉到 94。如果只看这两个数，结论是「这一项优化导致了回归」。打开 JSON 对比才发现：JS、CSS、请求数完全没变，只有图片小了 149 KB；SI 涨了 36%，而 SI 在资源变少的情况下不该涨 —— 这是模型抖动，不是回归。

要是当时只留了一个分数，这个判断就做不出来，我就会把一项其实有用的改动回滚掉。

## 一句话

**分数是估计值，字节数是测量值。** 需要给人看的时候给中位数和区间，需要自己做决定的时候看字节。
